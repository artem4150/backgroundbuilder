# ТЗ: конструктор векторных композиций

Дата фиксации: 3 ноября 2026. Срок: два дня со слов заказчика.
Этот документ — источник требований для реализации. Не добавлять функции сверх описанного без согласования с пользователем. Приоритет: предоставленное задание Figma и явные решения пользователя, затем технические предложения ассистента.

## Решения пользователя

- Веб-сервис, доступный по ссылке. Хостинг на компьютере пользователя со статическим IP; Docker Desktop установлен.
- Домен: backgroundbuilder.duckdns.org (DuckDNS), подтверждён пользователем.
- Frontend: Next.js + TypeScript. Backend: FastAPI. Хранение файлов: MinIO. Docker + Docker Compose. Nginx для проксирования.
- Облачная модель: Gemini. Доступность бесплатной квоты и конкретную модель проверить при подключении. API-ключ хранить на backend.
- Регистрации и аккаунтов нет.
- Только предоставленные SVG из Figma. Новые объекты не рисовать и не генерировать.
- Только предоставленные палитры. Не придумывать дополнительные схемы и произвольные цвета.
- Светлая тема. Качественный законченный интерфейс; визуальная основа обсуждалась как shadcn/ui с собственным оформлением, окончательный макет ещё не утверждён.
- Качество результата и соответствие Figma важнее числа функций.

## Исходное задание (текст пользователя, переносы нормализованы)

Разработать веб-сервис, который позволяет из отдельных компонентов (это отдельные иллюстративные объекты, из которых собираются иллюстрации) собирать различные комбинации композиций для иллюстраций в разных форматах.

Процесс должен быть автоматизирован.

Сценарий 1: человек должен задать метафору или заголовок, а программа сама собирает подходящие объекты в композицию.

Сценарий 2: человек вбивает название нужных компонентов, которые далее уже компануются в композицию.

### Ключевое ограничение

Сервис не генерирует новые объекты: итоговая композиция состоит только из элементов исходных 20 иллюстраций. AI-инструменты разрешены для разработки самого сервиса и анализирования метафор. Важно, чтобы объекты никак не менялись и в итоговой композиции был именно векторный формат.

Не обязательно разрабатывать отдельный сайт или приложение. Это может быть плагин для Figma (вся библиотека и компоненты как раз существуют в Figma).

### Что должен уметь сервис

1. Работа с SVG и библиотекой элементов:
- загружать или использовать заранее подготовленную кандидатом библиотеку из SVG-иллюстраций;
- корректно сохранять векторную структуру, цвета и пропорции элементов.

2. Сборка композиции:
- добавлять элементы из библиотеки на общий холст;
- перемещать, поворачивать, дублировать и удалять объекты;
- управлять порядком слоёв и собирать сцену из элементов нескольких исходных иллюстраций;
- давать выбор размера и цветовой схемы.

Работа с цветовой палитрой: не просто сохранять цвета элементов, а загрузка цветовой палитры в сервис и автоматическая перекраска композиции (как это сейчас делает плагин в фигме).

3. Экспорт:
- скачивать итоговую композицию в формате SVG;
- сохранять векторность и редактируемость объектов, не превращая результат в растровое изображение.

### Что прислать по итогам

- ссылку на работающий сервис или запускаемый проект с короткой демонстрацией;
- ссылку на репозиторий с исходным кодом;
- краткое описание архитектуры: как устроены хранение, извлечение и переиспользование SVG-элементов;
- список AI-инструментов, использованных при разработке, и 2–3 примера собранных композиций.

Важно: мы оцениваем качество решений и работающий результат, а не количество функций. Тестовое задание не будет использоваться компанией в коммерческих целях.

### Правила библиотеки и композиций

Иллюстрации делятся на 2 размера. Разница в детализации. Конструктор должен давать выбор размера и автоматически подгружать соответствующие элементы.

Сейчас существует 3 цветовые схемы, в будущем количество их может увеличиться.

Существуют Главные объекты (цветные) и фоновые (монохром). В зависимости от смыслов или композиции допустимо использование фоновых объектов или их отсутствие.

Цвета фонов могут использоваться в объектах. Цвета для объектов не могут использоваться в фонах.

Можно:
- композиция и расположение объектов;
- объект может менять состояние: главный или фоновый;
- цвета объекта.

Нельзя:
- менять пропорции объектов относительно друг друга;
- сам объект и его элементы (объект должен по сути просто копироваться);
- нельзя нарушать цветовую схему.

## Применение требований в реализации

- Gemini только интерпретирует запрос и выбирает идентификаторы существующих объектов. Не генерирует SVG/изображения и не изменяет геометрию.
- Подготовленная библиотека допустима: загрузку произвольных пользовательских SVG не добавлять.
- S/L — детализация объектов, отдельно от соотношения сторон холста. Подмена S/L простым масштабированием запрещена.
- Сохранять относительные размеры исходных объектов; не давать свободно масштабировать каждый объект. Для адаптации формата допустим общий масштаб сцены при сохранении соотношений.
- Поворот целого объекта включить: он прямо указан в основном задании. Не деформировать, не менять внутренние контуры и детали.
- Перекраска только по трём исходным схемам с сохранением ролей цветов. Загрузку палитры реализовать для исходных схем; конкретный формат импорта определить до реализации, не вводя произвольные новые палитры.
- Фоновые объекты необязательны, порядок слоёв управляемый.
- Примеры показывают квадратный, горизонтальный и вертикальный форматы. Точные размеры выбрать по исходникам/макету; произвольный размер не является согласованной дополнительной функцией.
- Экспорт SVG содержит векторные объекты и сохраняет редактируемость. Не растрировать.

## Границы объёма

Не включать без отдельного согласования: регистрацию, аккаунты, личные кабинеты, публичные ссылки на проекты, совместную работу, историю версий, галерею проектов, PNG/PDF-экспорт, генерацию новых объектов, произвольные палитры, загрузку сторонних SVG, полный мобильный редактор.

PostgreSQL и отдельный worker ранее предлагались ассистентом; обязательность пользователем не подтверждена. Не вводить их как согласованные требования. При необходимости обосновать отдельно.

## Критерии готовности

1. Оба сценария ввода приводят к композиции из разрешённых объектов.
2. Работают перемещение, поворот, дублирование, удаление и порядок слоёв.
3. Выбор S/L подставляет соответствующие исходники.
4. Выбор/загрузка исходной палитры автоматически перекрашивает композицию и соблюдает ограничения фона.
5. Работают форматы по примерам; относительные размеры и геометрия объектов сохранены.
6. SVG скачивается и открывается в векторном редакторе без потери структуры.
7. Сервис доступен по внешней ссылке; подготовлены репозиторий, инструкция запуска, демонстрация, архитектурное описание, список AI-инструментов и 2–3 примера.
